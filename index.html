A home for your AI team.

Open Terminal on your Mac. Paste this once. The script creates Documents/AI Operations with six role folders, project templates and ready-to-use instructions.

PASTE INTO TERMINAL · MAC
bash -c 'f=$(mktemp) || exit; trap "rm -f \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/mango-magic/mangomagic/main/setup-operations.sh -o "$f" && bash "$f"'

No Git or Python needed. Existing files are preserved. It opens your folder in Finder; it does not launch agents, schedule jobs or change your global settings. Read the script ↗

Prefer a download, or a different folder?

Download the starter ZIP and unzip it. To choose a destination with the script:

TERMINAL
bash -c 'f=$(mktemp) || exit; trap "rm -f \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/mango-magic/mangomagic/main/setup-operations.sh -o "$f" && bash "$f" --destination "$HOME/Desktop/AI Operations"'

The command is for macOS. On other systems, use the ZIP and a client that supports the workflow.

Want MangoMagic 7.1 in ChatGPT too?

Our ManyMangoes B2B sales instructions, powered by GLM 5.3 Flash through Ollama. This separate Mac installer pulls the model, checks it, registers it and gracefully restarts ChatGPT.

TERMINAL · RESTARTS CHATGPT
bash -c 'f=$(mktemp) || exit; trap "rm -f \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/mango-magic/mangomagic/main/install.sh -o "$f" && bash "$f"'

Using ChatGPT on the web?

Create a ChatGPT project, upload the relevant starter Markdown files and business sources, and paste the shared AGENTS.md rules into project instructions. Keep uploads current. A web project does not automatically read your Mac's folders, run the Mac installer or inherit its Ollama model. Local custom agent definitions apply to supported local Codex clients.

Use the prompts with the tools your account actually has. If file writing or delegation is unavailable, the assistant can return file contents and work through roles sequentially.

Teach it how your business works.

Start with five useful inputs: what you sell, who buys, claims you can prove, examples you like, and the outcome you need. The onboarding prompt turns them into a reusable business brief.

PASTE INTO YOUR PROJECT CHAT
Set up this AI Operations workspace for my business. Read AGENTS.md, 00_Command_Centre/BUSINESS_BRIEF.md, CURRENT_MISSION.md and 02_Agents/AGENT_ROSTER.md. First verify that you can read these files; if you cannot, explain the missing access without pretending setup worked. Ask me up to five short questions together to fill material gaps in the business brief. Use facts I provide; leave unknowns marked unknown. Preserve existing content. Recommend only the roles I need. Explain which custom agents are actually available in this client and which are just role instructions. Update the business brief, mission, roster and project_tasks.json. Show one useful first deliverable and its acceptance criteria. Do not run recurring tasks or send messages as part of onboarding.

Give it examples of responses you appreciate. Ask it to adapt its tone and level of detail, without personality labels.

Know where everything lives.

00_Command_Centre
Your business brief, task brief and handoff template.
01_Data
Source documents, sanitised conversations and a source register.
02_Agents
One folder and instruction file for each role.
03_Projects
One folder per outcome. Drafts, task evidence and checks.
04_Automations
Tested routines and records of actual schedules.
05_Deliverables
Reviewed work you can find, use and share.

At the root: AGENTS.md sets working rules, CURRENT_MISSION.md sets the priority, and project_tasks.json records actual progress.

Put the good work on repeat.

Run a task manually. Check the output. Fix the instructions. Then schedule it. Start with a daily priorities brief, a weekly sales review or a delivery check.

  1. Use the automation prompt below to define inputs, cadence, timezone, output and failure handling.
  2. Test the prompt in a normal project chat.
  3. Create the task in the app and verify it under Scheduled, including its timezone and enabled status.
  4. Review the first run. Keep the useful notifications; cut the noise.

For local-file schedules, keep the computer on, the app running and the project available. A Markdown file is a reusable brief, not a running schedule. Official scheduling guide ↗

T E A M

Brief the specialists.

One outcome. Clear ownership. One integrated result.

Read prompt
Read AGENTS.md, CURRENT_MISSION.md and project_tasks.json. Deliver [specific outcome] in 03_Projects/[project]. Use [source files] and meet [acceptance criteria] by [deadline]. If supported, delegate independent parts to up to three relevant specialists. Give each a role file to read, exact inputs, a separate output path, file scope and a definition of done. Use fewer agents when practical. If delegation is unavailable, work sequentially and say so. Integrate the work, verify it against the evidence, update the tracker and return the deliverable with any remaining decisions. Continue authorised work without unnecessary check-ins.

S A L E S

Turn conversations into a playbook.

Find what moves buyers forward, and what does not.

Read prompt
Read the approved offer and sanitised inbox conversations in 01_Data. Build a sales playbook for [buyer segment]. Find buying triggers, objections, useful questions and next steps. Cite anonymised source IDs and show sample size, counterexamples and whether a meeting was actually confirmed. Separate observed patterns from your suggestions. Do not invent conversion rates or personalisation. Produce three short draft response sequences, verify every business claim, and save the playbook and evidence in 03_Projects/[project]. Update project_tasks.json. Do not send messages.

R E S E A R C H

Make a decision with evidence.

Useful options, checked claims and a recommendation.

Read prompt
Research [decision] for [audience] using [approved documents and research scope]. Verify time-sensitive facts with primary sources when research tools are available. Record source dates and links. Separate facts, inference and unknowns; include conflicting evidence and what could change the answer. Save a one-page decision brief with options, recommendation, key risks and next action in 03_Projects/[project]. Check every material claim against its source. Update project_tasks.json and state any sources you could not access.

D E L I V E R Y

Keep going. Check the work.

Resume from the files and finish what is authorised.

Read prompt
Resume the current mission from AGENTS.md, CURRENT_MISSION.md, project_tasks.json and the latest handoffs. Inspect the actual outputs before trusting recorded status. Complete the highest-priority unblocked work within the authorised scope. Verify acceptance criteria and record evidence paths, failures and next actions. Never inflate completion percentages. Prepare the finished deliverable for owner review only after all required work and checks are done. If a decision or missing access blocks progress, state exactly what is needed and continue independent work. Return the result, its verification and the next decision.

A U T O M A T I O N

Build a routine worth keeping.

Prepare it, test it, then verify the actual schedule.

Read prompt
Prepare a recurring [job] for this project. Cadence: [schedule]. Timezone: [Area/City]. Inputs: [specific accessible files or connected tools]. Output: [file and success check]. Read 04_Automations/AUTOMATION_BRIEF.md and fill a copy for this routine. Define duplicate prevention, retry limit, stop condition and usage budget. Notify only on a meaningful change, actionable failure or required decision. Run one bounded manual test and inspect its output. Keep this a draft until I ask to schedule it; a saved file is not a scheduled task. Then verify the saved app schedule, timezone, enabled status and input access before reporting it active. Do not send messages, publish or spend as part of this routine.

Q U A L I T Y

Give it a proper final check.

Find material problems before they reach a customer.

Read prompt
Review [deliverable path] against [task brief] and its cited sources. Check factual claims, calculations, links, missing requirements and whether the output is useful to its intended reader. Distinguish checks actually performed from checks still needed. Return pass, needs changes or blocked, with evidence and specific corrections. Fix routine issues within the authorised scope, recheck them and update project_tasks.json. Keep owner approval separate from technical completion. If this reviews your own work, disclose that the review is not independent.

W H E N · S O M E T H I N G · D O E S N ' T · C L I C K

A few useful answers.

It says setup finished. Why does ChatGPT not know my files?

The script finished creating the workspace. Attach it as the primary folder of a local project and start a new chat there. Ask ChatGPT to name and summarise the mission file. A file existing on disk does not prove the app can read it.

Do I need MangoMagic for this system?

No. The workspace and prompts can be used with the model available in your app. MangoMagic 7.1 is our optional sales-focused instruction setup on GLM 5.3 Flash. Model availability, tools and scheduling depend on your client and account.

Will this use my existing agents?

It preserves existing files and global settings. Map your agents to folders in AGENT_ROSTER.md using ROLE_TEMPLATE.md. The six included project definitions are suggestions, not an import of your existing account configuration. Ask the app to verify the roles it can actually delegate to.

Is this training the model on my business?

It supplies context and instructions. It does not change model weights or make a public model know your private files. Only provide source material you want the selected model and connected tools to process.

What should I automate first?

A short internal priorities brief or a weekly delivery review. Give it a narrow input, a useful output and a check you can repeat. Test it before adding a schedule. Keep customer messaging and publishing within your explicit authorisation.
