Step 1. Build the workspace.

Open Terminal on your Mac. Paste this once. The script creates Documents/AI Operations with six role folders, project templates and the complete Build My Assistant playbook.

PASTE INTO TERMINAL · MAC
bash -c 'f=$(mktemp) || exit; trap "rm -f \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/mango-magic/mangomagic/main/setup-operations.sh -o "$f" && bash "$f"'

No Git or Python needed. Existing files are preserved. It opens your folder in Finder; it does not launch agents, schedule jobs or change your global settings. Read the script ↗

Prefer a download, or a different folder?

Download the starter ZIP and unzip it. To choose a destination with the script:

TERMINAL
bash -c 'f=$(mktemp) || exit; trap "rm -f \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/mango-magic/mangomagic/main/setup-operations.sh -o "$f" && bash "$f" --destination "$HOME/Desktop/AI Operations"'

The command is for macOS. On other systems, use the ZIP and a client that supports the workflow.

S T E P · 0 2

Step 2. Connect ChatGPT.

  1. In the desktop app, create a local project called AI Operations.
  2. Open the project menu: Edit project → Add folder. Choose your new AI Operations folder and make it primary.
  3. Start a new chat in that project. Continue to Step 3 and paste the assistant prompt.

The first check is real file access. If the assistant cannot read your mission and business brief, setup is not connected yet. Official project instructions ↗

Using ChatGPT on the web?

Create a ChatGPT project, upload the relevant starter Markdown files and business sources, and paste the shared AGENTS.md rules into project instructions. Keep uploads current. A web project does not automatically read your Mac's folders, run the Mac installer or inherit its Ollama model. Local custom agent definitions apply to supported local Codex clients.

Use the prompts with the tools your account actually has. If file writing or delegation is unavailable, the assistant can return file contents and work through roles sequentially.

Step 3. Build an actually useful assistant.

Your assistant should know what you do, how you like to work, what good looks like and when it can act. Our Team AI Operations method turns those answers into a personal operating brief.

  1. Understand your actual week. Use recent tasks, real examples and the work that never makes the calendar.
  2. Learn your working preferences. Answer first or detail first, how to deliver bad news, and examples of your voice. No personality labels in its replies.
  3. Make the work specific. Give each task a trigger, inputs, steps, output, quality check and permission level.
  4. Prove it on real work. Produce one useful deliverable, then choose three tasks for the first week. Record gaps and check the results.
PASTE INTO YOUR CONNECTED PROJECT CHAT
Build an actually useful assistant for me in this AI Operations workspace. Read START_HERE.md, AGENTS.md and 00_Command_Centre/BUILD_MY_ASSISTANT.md. First verify that you can read the files; if access is missing, say exactly what is missing. Use the context and permissions I have already given you. Ask only for material gaps, up to five concise questions together, and follow my preferred pace. Learn from real tasks and examples of my writing. Adapt your communication to my preferences without mentioning personality types. Follow the playbook to build my profile, specific task register and reusable assistant instructions. Mark facts, assumptions and gaps honestly. Preserve existing work, update project_tasks.json, and produce one useful first deliverable with checks. Prepare three practical tasks for week one and the rollout audit. Account connections, external actions and schedules need their actual tools and my authorisation; never report them active just because files exist.

Step 5. Put good work on repeat.

Run a task manually. Check the output. Fix the instructions. Then schedule it. Start with a daily priorities brief, a weekly sales review or a delivery check.

  1. Use the automation prompt below to define inputs, cadence, timezone, output and failure handling.
  2. Test the prompt in a normal project chat.
  3. Create the task in the app and verify it under Scheduled, including its timezone and enabled status.
  4. Review the first run. Keep the useful notifications; cut the noise.

For local-file schedules, keep the computer on, the app running and the project available. A Markdown file is a reusable brief, not a running schedule. Official scheduling guide ↗

Step 6. Add MangoMagic 7.1.

Our ManyMangoes B2B sales instructions on GLM 5.3 Flash through Ollama. This step pulls the model, checks it, registers it with ChatGPT and gracefully restarts the app. Skip it if you only want the workspace.

TERMINAL · RESTARTS CHATGPT
bash -c 'f=$(mktemp) || exit; trap "rm -f \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/mango-magic/mangomagic/main/install.sh -o "$f" && bash "$f"'

After the restart, choose MangoMagic 7.1. Images are supported. Light = Low/Light, Mango = High, Super Mango = Max. ChatGPT owns the slider labels.

All three use the same model and token rates. Extra reasoning can use more time and tokens; it does not guarantee a better answer. Ollama cloud usage is separate from your ChatGPT subscription. This is instruction customisation, not weight fine-tuning.

W H E N · S O M E T H I N G · D O E S N ' T · C L I C K

A few useful answers.

Does the everything command finish my assistant too?

It installs the files and model integration. Step 2 gives the project access to your folder. Step 3 uses your real work and preferences to build your assistant. An installer cannot answer those questions for you. The assistant prompt handles the setup conversation and checks its first result.

It says setup finished. Why does ChatGPT not know my files?

The script finished creating the workspace. Attach it as the primary folder of a local project and start a new chat there. Ask ChatGPT to name and summarise the mission file. A file existing on disk does not prove the app can read it.

Do I need MangoMagic for this system?

No. The workspace and prompts can be used with the model available in your app. MangoMagic 7.1 is our optional sales-focused instruction setup on GLM 5.3 Flash. Model availability, tools and scheduling depend on your client and account.

Will this use my existing agents?

It preserves existing files and global settings. Map your agents to folders in AGENT_ROSTER.md using ROLE_TEMPLATE.md. The six included project definitions are suggestions, not an import of your existing account configuration. Ask the app to verify the roles it can actually delegate to.

Is this training the model on my business?

It supplies context and instructions. It does not change model weights or make a public model know your private files. Only provide source material you want the selected model and connected tools to process.

What should I automate first?

A short internal priorities brief or a weekly delivery review. Give it a narrow input, a useful output and a check you can repeat. Test it before adding a schedule. Keep customer messaging and publishing within your explicit authorisation.
